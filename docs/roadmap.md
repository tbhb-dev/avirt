# Status: planned

Each phase is one commit that passes `mise run check`, its own checklist, and the regression suite below. Each phase also records the [performance metrics](./performance.md) for the stages it introduces.

- Add the Containerization runtime first. It supports the workload's HTTP/2 connection to its mediator over vsock, with avirthostd forwarding the bytes unchanged. It also supports SPIFFE mutual TLS.
- Remove the Apple container CLI runtime next, once the Containerization runtime matches current behavior.
- Phase 4 builds the Rust data plane in avirtmediatord and avirtedgeproxyd, before adding TLS interception, policy, or credential functions.
- Build the Docker Desktop runtime directly on the workload's HTTP/2 connection to its mediator and on a mediator without a network.

# Regression suite

## Status: implemented

Every phase runs this suite on every runtime it touches. The bypass checks run inside the agent's own process tree, by asking the agent to run a script, because a process started from outside the agent's tree isn't under its restrictions. Each check must fail, and fail fast:

- direct TCP (`curl --noproxy '*'`, bash `/dev/tcp`), UDP, DNS (`getent`, a Node resolver aimed at 1.1.1.1 and at the proxy host) and IPv6. Once the workload DNS stub exists, `getent` of an allowed name resolves through it and appears as a `dns` event, a name the policy denies gets `NXDOMAIN`, and DNS aimed at any other address still fails.
- Node `fetch` with every proxy variable unset.
- `/proc/self/status` shows capabilities at 0 and `NoNewPrivs: 1`.
- `su`, `mount` and the setuid binaries gain nothing, and `unshare -Urn` gets an empty network namespace.
- opening the workload's sockets directly gives `EACCES` (they're listed as `root:root 0600`, or owned by a per-process UID with mode 0600 once those processes exist), and no avirthostd socket exists anywhere in the sandbox container's filesystem.
- `/proc/1/fd`, `/proc/1/mem` and `/proc/1/environ` are unreadable, and the kernel refuses `kill -9 1`.
- CONNECT to `127.0.0.1`, `localhost`, `[::1]` and the host's own addresses gets 403 `private-dest`, and an absolute-URI `GET` gets 501 `plain-http`.

## Client and lifecycle checks

Positive checks, for each agent: a web fetch, `npm install left-pad` and a `git clone` of `octocat/Hello-World`. Each must produce allow lines in `logs/<workload-id>.ndjson` for the model API, example.com, registry.npmjs.org and github.com, all before `container_exit`.

Lifecycle checks:

- SIGINT mid-session removes the mediator and workload directory. The VM or container must also be absent.
- killing the mediator mid-session ends the workload with a `container_error` (freeze and resume from phase 3 on).
- after SIGKILL stops avirthostd, the next avirthostd start sweeps everything it left, and leaves the state directory untouched.

## Status: planned

Run the applicable checks on each affected runtime. Prompt the agent to run restriction checks from its own process tree. Run boundary checks as unrestricted root inside the guest. Include runtime processes and inherited descriptors.

### Network checks

- Permitted TCP, UDP, ICMP echo and DNS succeed over IPv4 and IPv6. Denied flows produce events, and no flow leaves except through the mediator and edge. Node fetch and other clients work without proxy variables.
- DNS to any address on TCP or UDP port 53 reaches `/dns`. Denied names get `NXDOMAIN`. Allowed names get synthetic answers. avirtmediatord refuses unknown synthetic addresses. Table exhaustion refuses allocation, and mediator restart preserves the table without address reuse.
- The sandbox VM has no network device. Deleting nftables rules makes TCP reach the TUN and receive RST. The transparent listeners reject original destinations that are loopback, unspecified, multicast, link-local, or within the TUN prefixes.
- The agent's capability sets are zero and `NoNewPrivs` is 1. `CAP_NET_ADMIN` is absent from the bounding set before other processes start. Seccomp denies `AF_PACKET`, `AF_NETLINK`, `AF_VSOCK`, and `IPPROTO_MPTCP`.
- Check refusal of direct access to another process's sockets, keys, memory, or descriptors. Check the inventory of runtime control channels and host-side vsock listeners. Each must enforce its destination outside the VM and refuse another workload's SVID.
- `private-dest` refuses non-global addresses and addresses assigned to the host's interfaces for TCP, UDP and ICMP, including an address added while the workload runs. Synthetic ranges never exempt the real upstream address.
- CONNECT-UDP enforces Context ID, immutable destinations, connected sockets, and capsule length and buffer limits before allocation. Stalled readers and writers in both directions must preserve control and DNS progress with bounded memory.
- QUIC accepts valid split Initials and refuses contradictory or excessive CRYPTO reassembly. Tests cover both versions, out-of-order data, Retry, Version Negotiation and 0-RTT with real clients. Intercepted names omit `h3` and `Alt-Svc`, and QUIC refusal permits TCP fallback.
- HTTP tests cover canonicalization and ambiguity on every request, pooling, redirects, cleartext termination without injection, gRPC trailers-only refusals and bidirectional streaming. A placeholder found after body forwarding resets the stream and records rejection.
- Websocket tests cover fragments, continuation and control frames, extension refusal and Close injection between websocket frames in both directions. SSH tests cover placeholder authentication, host-key pins, strict git commands, refusal of unauthorized SSH channel and forwarding requests, and workload caps.
- Ping tests cover type, length, rate, caps on outstanding requests, and Linux identifier rewriting. UDP and ICMP idle timeouts, TCP half-close, explicit tunnel drain, keepalive, h2 header-list and rapid-reset bounds need conformance coverage.

# Unscheduled

- **Linux host runtime.** A KVM microVM per workload and mediator with vhost-vsock, mapping to the workload's HTTP/2 connection to its mediator over vsock, whose bytes avirthostd forwards unchanged. It needs `/dev/kvm`.
- **Windows host runtime.** Hyper-V through HCS with hvsock, mapping to the same connection. It needs Hyper-V Administrators membership. Restrictions on host connections on Windows remain open (see [build and platforms](./build-and-platforms.md#open-questions)).
- **Pure-Rust Apple runtime (deferred).** VMs through `objc2-virtualization`, with a Rust guest init in place of vminitd, replacing the Swift shim.

# Open questions

Resolve these before building the phases that depend on them:

1. **Codex with a placeholder `auth.json`, end to end (phase 10).** Check the synthesized refresh response through Codex's token persistence, its reload from disk on a 401, and codex-acp's login path, using a hand-made placeholder `auth.json` against a stub gateway and then a forced real refresh.
2. **Codex's sandbox under the planned seccomp filter (phase 11).** Does workspace-write need `CLONE_NEWUSER` or nested seccomp? Docker's default profile also blocks `unshare`. The answer affects both runtimes.
3. **The SPIFFE verifier and rotation (phase 3).** Run conformance tests against the X.509-SVID rules (chain to bundle through the issuing CA, authorization of the exact peer ID, name constraints, no web roots) and against the workload-signed inner request, plus a soak with a 2-minute lifetime and long streams across rotations.
4. **Landlock in the running Apple guest (phase 11).** Expect `landlock_create_ruleset(NULL, 0, LANDLOCK_CREATE_RULESET_VERSION)` to return 7 inside a Containerization sandbox container. It must return at least 6, since a kernel `lsm=` argument could drop Landlock (see [workload kernels](./landlock.md#workload-kernels)).
5. **CA coverage under termination (phase 8).** Does Claude Code's `NODE_EXTRA_CA_CERTS` path cover every client it uses, and which `/api/*` calls does it make at startup?
6. **cgroup v2 in the guests (phases 3 and 6).** Does each runtime's guest give avirtinitd a writable cgroup v2 hierarchy with `cgroup.freeze` and `cgroup.kill`? Docker mounts `/sys/fs/cgroup` read-only by default. Check with a fork bomb during forced mediator termination.
7. **Containerization socket presentation (phases 3 and 5).** Does the runtime's vsock-to-Unix-socket forwarder present vsock connections in both directions as the Unix sockets the sandbox container and the mediator need? Do those sockets have the ownership and modes the per-process UIDs require?
